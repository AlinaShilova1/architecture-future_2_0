### Технический радар «Будущее 2.0»: стратегия трансформации

| Квадрант | Технология / Подход | Как поддерживает бизнес-сценарии | Бизнес-эффект и обоснование |
| :--- | :--- | :--- | :--- |
| **Принять** | **Облачные DWH** (Snowflake, BigQuery) | **Мгновенная отчетность**, консолидация KPI из разных доменов. | **Эффект**: Сокращает time-to-market для аналитики с **часов до минут**. **Почему**: Автомасштабирование, разделение вычислительных и storage ресурсов, оплата за использование. |
| | **Event-Driven Архитектура** (Kafka) | **Асинхронная интеграция** доменов (напр., событие "платёж получен" → доступ к услуге). | **Эффект**: Повышает отказоустойчивость и скорость реакции систем. **Почему**: Замена жесткой синхронной шины (Camel) на гибкую, позволяющую доменам развиваться независимо. |
| | **Контейнеры & Kubernetes** | **Независимое развертывание и масштабирование** сервисов в каждом домене. | **Эффект**: Ускоряет вывод новых функций (деплой несколько раз в день). **Почему**: Стандартизация среды выполнения, изоляция, эффективное использование ресурсов в облаке. |
| | **API First** (REST/GraphQL) | **Четкие контракты** для интеграции между доменами и с внешними партнерами (фармацевтика). | **Эффект**: Нового партнера можно подключить за **недели**, а не месяцы. **Почему**: Позволяет строить экосистему по принципу "платформа". |
| **Проверить** | **Data Mesh** | **Самообслуживание данными**: каждый домен (финтех, ИИ) владеет своими "Data Products". | **Эффект**: Устраняет DWH как единую точку отказа и узкое место. **Почему**: Прямо соответствует цели независимого развития направлений. Требует культурных изменений. |
| | **Infrastructure as Code** (Terraform) | **Воспроизводимость и контроль** облачной инфраструктуры для каждого домена. | **Эффект**: Снижает риски дрейфа конфигураций, ускоряет создание тестовых сред. **Почему**: Критично для соблюдения compliance в облаке. |
| | **CI/CD для данных** (DVC) | **Версионирование датасетов и моделей**, автоматизация тестирования пайплайнов. | **Эффект**: Повышает качество и надежность данных в портале самообслуживания. **Почему**: Без этого невозможно доверие к данным при self-service аналитике. |
| **Оценить** | **Граф знаний** | **Персонализированная медицина**, обнаружение связей "лекарство-диагноз" для R&D с партнерами. | **Потенциал**: Создание уникального конкурентного преимущества. **Стратегия**: Исследовать в пилотном проекте с фармацевтическим партнером. |
| | **Federated Learning** | **Обучение ИИ-моделей** на распределенных данных клиник без их централизации. | **Потенциал**: Улучшение моделей при строгом соблюдении конфиденциальности. **Стратегия**: Решение для будущего масштабирования ИИ-сервисов. |
| **Устарело** | **Монолитный DWH** (SQL Server 2008) | **Тормозит все аналитические сценарии**, является единой точкой отказа. | **Проблема**: Отчёты строятся часами, изменения рискованны. **План**: Поэтапная миграция агрегированных данных в облачное DWH, превращение в архив. |
| | **Серверная шина ESB** (Apache Camel) | **Создает жесткую связность**, узкое место для интеграции. | **Проблема**: Любое изменение требует глобальных тестов. **План**: Замена на Event-Driven архитектуру (Kafka) для асинхронного взаимодействия. |
