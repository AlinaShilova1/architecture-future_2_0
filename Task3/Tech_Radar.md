### Технический радар «Будущее 2.0»

| Кольцо | Категория | Технология | Роль и поддерживаемые бизнес-сценарии | Обоснование решения |
| :--- | :--- | :--- | :--- | :--- |
| **Adopt** | **Платформы** | **AWS / Azure (облако)** | **Масштабируемая инфраструктура** для всех доменов. Сценарий: быстрый запуск новых сервисов (финтех, ИИ) и эластичное масштабирование аналитики. | Стратегическое решение для сокращения затрат на железо и ускорения time-to-market. |
| | | **Kubernetes** | **Стандарт развёртывания** для микросервисов всех доменов. Обеспечивает независимое масштабирование и обновление. | Индустриальный стандарт, дающий предсказуемость и переносимость между облаками. |
| **Adopt** | **Инструменты** | **Apache Kafka** | **Event Bus** для асинхронной интеграции доменов. Сценарий: событие «платёж получен» автоматически открывает доступ к мед. услуге. | Замена синхронной шине (Camel). Повышает отказоустойчивость и снижает связность систем. |
| | | **Terraform** | **Infrastructure as Code** для воспроизводимого развёртывания облачных ресурсов каждого домена. | Критично для compliance, безопасности и скорости создания сред в мульти-облачной стратегии. |
| **Adopt** | **Методы** | **Event-Driven Архитектура** | **Основа интеграции** независимых доменов. Позволяет финтеху, медицине и ИИ обмениваться событиями без прямых вызовов API. | Прямо решает задачу интеграции новых направлений без изменений в ядре DWH. |
| | | **API First** | **Единый контракт** для внешних партнёров (фармацевтика, производители). Сценарий: подключение нового партнёра за недели. | Позволяет строить экосистему, превращая компанию в платформу. |
| **Trial** | **Методы** | **Data Mesh** | **Организационная парадигма**, где каждый домен (финтех, ИИ) владеет своими «Data Products». Ключ к независимости от центрального DWH. | Многообещающий, но требующий культурных изменений подход. Пилот в одном домене снизит риски. |
| **Trial** | **Инструменты** | **DataHub / Apache Atlas** | **Каталог данных** для портала самообслуживания. Позволяет сотрудникам находить и использовать доверенные данные. | Без этого инструмента реализация Data Mesh и эффективного self-service аналитика невозможна. |
| **Assess** | **Методы** | **Federated Learning** | **Метод обучения ИИ-моделей** без централизации конфиденциальных медицинских данных. Потенциал для улучшения диагностики. | Многообещающая технология для будущего, требующая оценки сложности и зрелости инструментов. |
| **Hold** | **Платформы** | **Локальный SQL Server 2008** | **Текущее монолитное DWH** — основное узкое место, из-за которого отчёты строятся часами. | Подлежит плановому выводу. Все новые проекты должны использовать облачное DWH. |
| **Hold** | **Инструменты** | **Apache Camel (ESB)** | **Устаревшая интеграционная шина**, создающая жёсткую связность и являющаяся точкой отказа. | Заменяется на асинхронную шину событий (Kafka) в новой архитектуре. |
| **Hold** | **Методы** | **Монолитная архитектура с единым DWH** | **Текущее состояние**, когда вся бизнес-логика и данные смешаны, что тормозит развитие. | Противоречит всем стратегическим целям компании. Переход к доменной архитектуре обязателен. |

### Стратегические выводы из радара

1.  **Фокус на «Adopt»** — это **новая техническая основа** компании. Быстрое и массовое внедрение этих технологий решит проблемы с производительностью, масштабируемостью и надёжностью.
2.  **Ключевой элемент трансформации в «Trial»** — **Data Mesh**. Это не просто технология, а **организационно-техническая парадигма**, которая напрямую ведёт к достижению главной бизнес-цели: независимому развитию направлений. Пилот должен быть запущен в ближайшие 6 месяцев.
3.  **Чёткий план по «Hold»** — необходим график вывода устаревших систем. Например, «заморозка» изменений в старом DWH и параллельный перенос отчётов в облако.
