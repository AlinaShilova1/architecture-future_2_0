### Обоснование разделения на домены

Разделение основано на **принципе bounded context (ограниченного контекста)** из DDD. Каждый домен владеет своими данными и логикой, предоставляя другим доменам только то, что им нужно, через четкие контракты (API/события).

| Домен | Владеет данными | Предоставляет другим доменам | Зачем нужно разделение? |
| :--- | :--- | :--- | :--- |
| **Финтех-домен** | Счета, кредиты, транзакции, финансовая отчетность. | 1. **События** о платежах. <br> 2. **Агрегированные KPI** (выручка, оборот) для DWH. | **Независимость**: Новый финтех-продукт (кредит, страхование) разрабатывается и тестируется внутри домена без изменений в мед. системах. **Безопасность**: Финансовые данные изолированы. |
| **Медицинский домен** | Мед. карты, диагнозы, снимки, история болезни (PII). | 1. **Анонимные данные** для ИИ-анализа. <br> 2. **События** о приемах. <br> 3. **Агрегированные метрики** (кол-во пациентов) для DWH. | **Комплаенс**: Чувствительные мед. данные никуда не уходят в сыром виде. **Скорость**: Клиники могут развивать EHR, не согласуя изменения с банком. |
| **ИИ-Сервис домен** | Обученные модели, результаты анализа, обогащенные данные. | **API** для анализа снимков и **обогащенные данные** (без PII) для DWH. | **Инновации**: ИИ-команда может итеративно улучшать модели, развертывать их в облаке, не затрагивая рабочее окружение клиник. **Масштабируемость**: Нагрузка на ИИ изолирована. |
| **Аналитический домен** | Агрегированные, очищенные, готовые для анализа данные в DWH. | **Единый портал самообслуживания** с отчетностью и дашбордами. | **Производительность**: DWH заточен под аналитику, а не под операционную логику. **Time-to-market**: Новый отчет создается из готовых витрин за минуты, а не часы. |
| **Партнерский домен** | Данные партнера (каталог лекарств, спецификации оборудования). | **Стандартизированные API** для обмена. | **Гибкость интеграции**: Нового партнера подключают через единый шлюз, не внося изменений в ядро DWH или EHR. |

### Преимущества такого разделения для бизнеса

1.  **Ускорение вывода продуктов в 2-3 раза**. Финтех-команда может выпустить новый кредитный продукт, используя только свой Data Lake и API, без сложных согласований с командой клиник и без модификаций монолитного DWH.
2.  **Снижение операционных рисков и затрат**. Падение производительности ИИ-сервиса не повлияет на обработку платежей в банке. Обновление EHR не сломает финансовую отчетность.
3.  **Включение новых партнеров за недели, а не месяцы**. Для подключения фармацевтической компании нужно лишь описать новый контракт в API Gateway и настроить pipeline передачи **уже анонимизированных данных** из Медицинского Data Lake.
4.  **Прямой путь к облаку и отказ от легаси**. Каждый домен может мигрировать в оптимальную для него облачную среду (например, ИИ-домен — в облако с GPU, Финтех-домен — в среду с усиленной безопасностью) по собственному графику.

**Итог**: Это разделение превращает DWH из **бутылочного горлышка**, в которое встроена вся логика, в **мощный аналитический двигатель**, который питается уже подготовленными, качественными данными от независимых, быстро развивающихся бизнес-доменов.
